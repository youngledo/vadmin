# 安全说明

## 身份与引导账户

首个版本只提供本地用户名和密码登录。数据库为空时，启动过程会创建一个 `admin`
账户、`administrator` 角色，并将当前权限目录中的所有权限授予该角色。

- `development` profile 可以使用 `change-me` 作为仅限本地的回退密码。
- 任意非 `development` profile 在空数据库启动时必须设置
  `APP_BOOTSTRAP_PASSWORD`，否则应用会拒绝启动。
- 引导密码只用于创建第一个管理员；已有用户时不会覆盖密码或角色。
- 生产环境必须从密钥管理系统、部署平台密钥或受保护的环境变量注入引导密码，
  不要将 `.env`、密码、令牌或数据库备份提交到仓库。

当前版本不包含 OIDC、SAML、LDAP、MFA、多租户或行级数据权限。这些能力应通过
明确的认证或授权适配器设计引入，不能以绕过平台用例检查的方式直接加到视图中。

## 授权边界

权限代码是唯一的授权词汇，格式为 `领域:资源:动作`，例如
`customer:customer:update`。角色只是可配置的权限集合。

同一个权限代码在四处生效：菜单投影、Flow 路由检查、按钮等交互控制，以及平台
用例的最终检查。前三者改善体验，平台用例检查才是不可绕过的安全边界。不要仅靠
隐藏按钮或前端导航来保护写操作。

权限目录由代码定义并在启动时同步到数据库。管理员可以将目录中的权限授予角色，
但不能在 UI 中随意创建新的权限代码。

## 错误与审计

核心层只表达业务失败代码和安全的字段信息。自定义 HTTP/MVC API 会将已映射的
失败返回为 RFC 9457 `application/problem+json`，其中包含稳定的错误类型、HTTP
状态、`errorCode`、安全的详情、字段错误及关联 ID。不要在 Problem Details 中返回
堆栈、SQL、密码、令牌或敏感元数据。

Vaadin Flow 的 RPC 和导航不是 REST API：当前验证失败显示为安全的通用提示，访问
被拒绝会进入 403 视图，其他失败进入 500 视图，而不会强行包装成 Problem Details。
业务失败仍携带字段错误，以便未来的表单绑定器按字段呈现，但通用 Flow 错误呈现器
不会将它们直接暴露给用户。

每个 HTTP 请求接受或生成 `X-Correlation-Id`，并在响应头、日志 MDC、审计记录和
Problem Details 中使用它。排障时应记录并提供该 ID，而不是复制敏感请求内容。

成功的管理操作与其审计记录在同一数据库事务中写入。审计数据不得记录密码哈希、
明文密码、令牌、SQL 或堆栈。
